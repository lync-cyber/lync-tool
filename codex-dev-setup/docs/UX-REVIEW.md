# 首页与设置流程调研及对抗性审查

审查日期：2026-09-13。本文记录本轮交互取舍、源码审查发现和验收边界，便于后续维护者理解为什么减少入口、合并确认，以及哪些步骤仍需要人工处理。

## 证据范围

依据包括用户提供的终端日志，以及本轮 `Start-CodexSetup.ps1`、检测、计划、执行、报告模块和现有行为测试的源码。另使用官方文档及 GitHub CLI 官方源码对照交互设计。没有取得产品截图，也没有开展截图或视觉审计；结论不涉及字体、颜色对比度或真实终端尺寸的验收。

对抗性审查针对修改中的工作树，重点检查正常路径之外的输入、作用域变化、部分成功、无人值守及重启边界。下面的函数名用于定位职责，不记录容易随修改失效的行号。缺陷“已确认”表示已在初审版本找到触发链路，不等于最终补丁已经通过回归测试。

本轮没有为验证安装路径而安装软件、重置发行版、提升权限或重启开发机器。模拟调用只能证明流程与数据处理，不能证明真实 Windows 安装或 Desktop 集成成功。

## 成熟工具可借鉴的行为

| 来源及事实 | 对本工具的具体取舍 |
| --- | --- |
| GitHub CLI 将交互配置放在 `gh auth login`；已有选项可直接表达信息，自动化另有无交互入口。[官方手册](https://cli.github.com/manual/gh_auth_login) | 首页围绕用户目的组织；命令参数与向导复用现有执行逻辑。不要为了向导再实现一套检测或安装器。 |
| `gh auth login` 的 `NewCmdLogin` 只有在 `CanPrompt()` 且没有提供令牌时启用交互，并把 `Interactive` 传入下层流程。[官方源码](https://github.com/cli/cli/blob/trunk/pkg/cmd/auth/login/login.go) | `-NonInteractive` 必须传到外部安装边界。仅跳过工具自身的 `Read-Host` 不够；下游程序也可能等待输入。 |
| WinGet 分别提供精确 ID、来源、接受协议、静默安装和禁用交互等参数。[官方安装文档](https://learn.microsoft.com/en-us/windows/package-manager/winget/install) | 计划明确包名和来源；使用已有安装封装。上层确认过的常规操作无需按模块再确认，但无交互模式必须有真实行为保证。 |
| WSL 提供安装后不启动发行版的 `--no-launch`；`.wslconfig` 更改需要 WSL 虚拟机停止并重启才生效。[安装命令](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)、[配置生效说明](https://learn.microsoft.com/en-us/windows/wsl/wsl-config) | 区分已安装、待初始化、待重启、已验证；不能把配置文件匹配当作运行时已生效，也不能把进程退出当作整条部署链完成。 |

另参考社区维护的 [Command Line Interface Guidelines](https://clig.dev/#interactivity)：输入不可交互时不要等待提示，允许退出，对坏输入提供明确反馈。该指南不是强制标准；这里采用的是与部署工具实际问题对应的建议。

上述事实支持“按目的分组、显式确认具体变更、保留执行上下文”的方向。推荐首页的具体数量和标签是本项目的设计判断，不能归因于某个工具规定所有 CLI 都必须采用相同菜单。

## 三种候选方案

| 方案 | 用户路径 | 优点 | 成本与问题 |
| --- | --- | --- | --- |
| A：保留原首页，精简文案 | 检查、设置、完整检查、重新检查仍并列 | 修改最少 | 用户仍要先理解检查深度和模式差异；检查到修复依然容易绕回首页。无法解决主要路径问题。 |
| B：按目的收敛首页，结果页继续 | 开始或修复、仅检查、项目配置、更多 | 新用户有单一推荐入口；保留只读需求和维护入口；可复用现有工作流 | 需要修正结果页转换和工作范围，但不需要新框架。推荐。 |
| C：启动即全自动向导 | 启动后直接检查，之后决定执行或退出 | 少一次首页选择 | 对日常检查、导出和回滚用户成本更高；自动深检会启动发行版。仍须保留维护和退出路径，容易出现另一套隐藏菜单。 |

选择 B。保留简单文本输入，避免为了几个选项引入全屏 TUI、焦点管理或新交互库。

目标首页：

```text
[1/Enter] 开始或修复（推荐）
          检查 → 确认变更 → 设置 → 验证
[2]       仅检查
[3]       初始化项目配置
[M]       更多：导出设置、撤销更改、Desktop 指南
[0]       退出
```

“开始”和“修复”使用相同的状态检测及差异计划。已匹配目标的组件跳过；检测失败保留为未知，不自动推断需要重装。仅检查采用明确的完整范围，首页文案应说明会启动目标发行版进行 Linux 检查；它不应用配置变更。

## 从旧路径到新路径

| 场景 | 原路径的问题 | 目标路径 |
| --- | --- | --- |
| 首次设置 | 选择设置 → 尚无计划先问 Y/N → 检查 → 计划确认 → 模块或动作继续确认 | Enter → 完整检查 → 列出实际变更及目标 → 一次确认 → 按依赖执行 → 验证 → 结果页给下一步。 |
| 先检查后修复 | 检查完返回首页，重新选设置，再次走入口确认 | 仅检查 → 结果页“继续设置” → 更新必要状态并展示变更 → 确认执行。保持同一进程，不要求用户重新启动工具。 |
| Ubuntu 安装后继续 | 安装命令结束容易被直接视为成功或统一要求重启工具 | 安装 → 检查实际发行版状态 → 已就绪则继续已有依赖链；需初始化或系统重启时停止依赖步骤并保留原因。 |
| 输入错误 | `x` 等非法输入可能使提示输出再次抛错 | 明确有效选项并在原菜单重新读取。不得默认为执行。 |
| 部分失败 | 通用完成指南让用户猜测哪些步骤需要重做 | 保留成功结果，列出未完成项；结果页可重新检查或继续设置。重试前重新检测，避免盲目重复写入。 |
| 项目初始化 | 多文件逐个确认，错误路径难以替换；重新检查可能扩大到全机操作 | 选择可修改的项目路径 → 项目文件变更预览 → 一次覆盖选择 → 写入并验证；后续检查和重试保持项目范围。 |
| 导出、回滚、查看指南 | 低频维护项与初次设置争夺首页注意力 | 放在“更多”；回滚先展示具体清单再确认，指南直接打开，不添加无意义确认。 |

结果页中的动作必须真的可用：没有待处理操作时，不提示用户选择不存在的“继续设置”；全部跳过时，不展示“设置完成”；检测失败时，不给出确定的“组件缺失”评分。

## 对抗性发现与最小修复

以下为初审发现记录。根修复流程应在完成后更新状态；“待回归”不能当作已验证。

| 编号／初审状态 | 触发条件与实现位置 | 最小修复及验收 |
| --- | --- | --- |
| U1：已修复，模拟回归通过 | `Show-WorkflowSession`：项目初始化结果页选择重新检查，再选择继续设置。初审纯模拟调用实际依次产生 `Detect apply=False deep=True`、`Apply apply=True deep=True`，项目操作扩大成全机设置。 | 会话保存原工作范围，检查与应用独立表达；项目计划始终过滤项目动作及阻塞原因。回归保证所有后续转换都不出现宿主安装动作。 |
| U2：已修复，模拟回归通过 | `Set-ProjectTemplates` 在循环内对每个不同的既有文件单独询问；最多连续询问四次，还缺少统一变更预览。 | 先计算新增、不变及待替换文件；合并一次覆盖选择。复用模板生成与现有写入函数，不为预览再复制一套生成器。 |
| U3：已修复，模拟回归通过 | `Install-WslDistribution` 初审无 `NonInteractive` 参数，`Invoke-SetupAction` 未将无人值守要求传到此分支，最终启动可等待输入的外部进程。 | 传递并执行该约束。当前能力不足以无交互初始化时，明确返回待人工处理且阻塞依赖操作；不能静默进入用户名、密码或 Shell 提示。无需在本轮增加自动创建 Linux 用户的子系统。 |
| U4：已修复，源码复核 | 首页项目入口仅当 `ProjectPath` 为空才询问；第一次输入错误的非空路径，返回首页再选项目仍复用该值。 | 每次项目入口允许修改路径；无效输入留在路径选择处。覆盖错误路径重输、取消、切换第二个项目的测试。 |
| U5：会话修复及模拟回归通过；真实 VM 待验收 | `Get-WslNetworkInfo` 读取配置文件；设置网络返回待重启后，结果页重检会替换上轮结果。旧 WSL VM 仍在运行时，配置匹配可能掩盖待重启状态。 | 文案区分文件配置与生效验证；会话保留未解决的重启提醒，只有有依据时清除。不要自动关闭全部发行版；不必为此建立常驻进程或跨重启状态机。 |
| U6：已删除重复分支，旧确认策略回归通过 | `firstRunWhatIf=true` 时，“开始或修复”先强制预览，结果页继续后再次完整检查并展示同样的确认。初审默认值为 false，因此这是兼容配置路径的问题；最终默认配置已移除此字段。 | 统一到“先展示计划，再确认执行”；删除首次会话专用分支，保留显式 `-WhatIf` 与 Plan 模式。旧配置字段可兼容读取，但不得另建执行路径。 |

日志中的缺少 `error` 属性、WSL 未知被显示为缺失、`Lines` 空字符串绑定异常，与以上交互缺口共同纳入本轮修复。它们是原始故障证据；是否已消除应以本轮行为测试和实际平台验证记录为准。

## 确认的边界

常规流程只保留针对已展示变更的统一确认。删除检测前确认、每模块确认和已被统一确认覆盖的重复 Y/N。查看指南、只读检测和非法输入修正不需要确认。

明确展示目标后，覆盖已有项目文件应合并处理；用户拒绝覆盖时保留原文件，并显示哪些文件未应用。不要把每个文件都变成一次独立决策。确实超出常规计划的高影响权限变更，以及可能终止用户工作的操作，需要直接说明影响；相关提示不能伪装成已完成的普通配置步骤。

`moduleConfirmation=Never` 等旧配置不应使首页“确认前不会应用设置”的承诺失效。交互向导与明确的无人值守命令应采用清楚一致的策略，避免一处设置名控制入口、模块和动作三个层次。

## 连续完成的实现边界

本轮目标是消除工具自身造成的重新启动需求。会话内“检查 → 修复 → 验证 → 重试”可以通过已有工作流的返回结果循环完成；安装成功后的后续步骤使用已有动作依赖。一次操作失败只阻塞依赖它的步骤，独立动作可继续并保留结果。

Windows 功能启用要求的系统重启、首次创建 Linux 用户、sudo 认证和 Desktop 手动设置是外部边界。需要系统重启时不能承诺同一进程继续；应展示原因、报告路径和重启后的单一入口。重启后重新检测实际状态，跳过已完成步骤即可，不需要本轮增加计划任务、开机自启或自动恢复守护进程。

WSL 重启与 Windows 重启必须分开说明。`wsl --shutdown` 会终止所有正在运行的发行版，不能为了减少一个步骤就自动调用。[Microsoft 命令说明](https://learn.microsoft.com/en-us/windows/wsl/basic-commands#shutdown)

## 防止过度设计与重复实现

- 一个菜单输入函数负责空输入、合法选项和错误重试；不要同时保留多个等价读取循环。
- 一个检测结果约定区分可用、缺失、未知和未检查；不要靠界面文案反向推断状态。
- 复用现有命令捕获函数。进程启动失败、超时与真实非零退出分别记录，无须再建 WSL 专用执行框架。
- 复用现有动作顺序与 `dependsOn`；当前动作数量不需要通用 DAG 调度器。
- 只在明确有重复调用且语义相同处抽取函数。为单处简单条件建立类、策略对象或注册表没有收益。
- 删除无调用的选择器、无消费者的状态字段和被合并流程取代的分支；配置兼容与实际执行逻辑分开处理。
- 已有模板生成器、文件备份和写入校验继续作为唯一实现。预览与执行可以共享结果，不能复制生成规则。
- 外部操作不可自动完成时给出具体下一步，不用重试循环、隐藏等待或乐观评分掩盖缺失能力。

## 验收要求

行为回归应覆盖非法菜单输入、一次确认、仅检查不应用设置、仅检查直接转修复、项目作用域保持、错误路径重输、四文件合并覆盖、无人值守不进入交互安装、部分失败后的依赖跳过及待重启提示保留。测试重点是用户可观察的状态与动作，不依赖菜单文案的精确排版快照。

按仓库脚本分别运行 Windows PowerShell 源码与行为检查、WSL 原生检查；真实安装、权限提升、Windows/WSL 重启、回滚和 Desktop 集成在指定 Windows 测试机验证。未运行的平台检查必须明确记录，不将模拟输出写成真实部署证据。具体执行结果以本轮验证记录为准。

## 本轮修复与验证记录

本轮将上述流程问题和对抗性审查补充的实现错误一起修复：应用未知项为空时的严格模式异常、报告空行与空剩余列表绑定、WSL 查询与深检失败误报缺失、现代 Store WSL2 被旧 WSL1 功能状态误导、用户规则文件换行导致反复要求更新、路径转换错误，以及大 stdin/输出管道互相等待导致超时失效。

已删除原任意权重评分、检测前确认、逐模块确认、不存在的网络选择器调用、首次预览分支、无消费者的检查范围字段和无入口的报告快捷分支。复用已有检测、依赖顺序、文件备份与进程捕获；没有新增安装器、菜单框架、后台恢复服务或通用流程引擎。

- Windows PowerShell：`pwsh -NoProfile -File tests/Run-All.Tests.ps1` 通过，包含 15 个 PowerShell 文件语法检查、行为测试、检测/工作流/版本选择回归及 5 个实际临时进程管道场景。
- Windows 本机只读 Plan：应用清单为 Known，无发行版的 WSL `-1` 输出识别为 NoDistribution，工具链为未检查；生成安装、设置默认版本/发行版、配置工具链的连续依赖计划。未执行这些变更。
- Windows 真实向导只读冒烟：向子进程输入非法选项 x、仅检查 2、回车返回、0 退出；错误输入被重新提示，检查与报告完成，退出码为 0。捕获器显式统一子进程的 UTF-8 输出编码，不以终端截图声称视觉验收。
- WSL 原生 `tests/run-wsl-tests.sh` 未运行：当前没有可用发行版。真实安装、UAC、系统及 WSL 重启、真实软件包回滚、Desktop 双通道集成未执行，需专用测试环境完成。
- 当前会话的重启提醒只有明确选择停止 WSL 且命令成功后才清除；新进程不恢复旧会话。报告和指南仍要求核对运行时生效，不宣称配置文件匹配等于 Desktop 或 VM 验收。

补充修正：shutdown 失败的旧回归用例使用宽泛的 `Assert-Throws`，错误地把后续模拟输入队列耗尽当作通过依据。该用例现已提供完整退出输入，并精确断言预期诊断、只读复检和两项待重启状态；预期错误被捕获验证，不再直接混入测试日志。负向验证分别制造队列耗尽和错误诊断，两者都返回退出码 1，且不输出全部通过；恢复正常用例后整套测试通过。
