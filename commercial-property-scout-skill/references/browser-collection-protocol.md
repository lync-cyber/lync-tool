# Browser Collection Protocol

用于 Codex Desktop / 带网页操作能力的 worker。

## 用户可见浏览器硬要求

- 房源平台的入口访问、筛选、翻页和详情页核验必须使用用户可见且可人工接管的交互式浏览器；支持可见性控制时，在访问第一个平台入口前设为可见。
- 采集期间保留正在操作的标签页，不在后台另开不可见会话替代它。页面可能触发验证时，用户应能同步看到同一页面状态。
- 后台网页抓取、搜索引擎、HTTP 客户端或文本化网页工具只可用于市场基准、辅助发现和交叉核验。它们不算高优先级房源平台的直接访问，不能单独生成 `completed_*`、`blocked_captcha`、`blocked_login` 或 `access_limited` 终态。
- 若交互式浏览器不可用，记录浏览器不可用及已尝试的恢复动作；不得静默改用后台抓取并把结果冒充平台直访。
- 来源状态、当前 URL、截图和页面证据必须来自同一个用户可见浏览器会话。搜索结果索引或后台抓取响应只能标注为辅助证据。

## 必查主源顺序与故障闸门

先分别访问贝壳和链家，且把两者作为独立来源记录。两者都完成前不得访问房天下、安居客、58 或其他房源发现平台。

任一必查主源出现登录、验证码、限流、超时、空白页、入口失效、筛选器无法保持、浏览器控制失败或其他妨碍完成计划内搜索的问题时，立即停止所有自动操作和后续来源采集。保留当前标签页，记录 URL、截图、故障表现和需要用户执行的动作，并等待用户明确回复。不得切换平台继续凑候选，也不得生成临时榜单或报告。用户确认恢复后，从同一来源、同一标签页和中断通道继续。

## 每个来源的固定动作

1. 在 `source_plan.json` 把该来源更新为 `in_progress`，记录开始时间和入口 URL。
   - 优先读取 `source-registry.json` 中当前城市的 `entry_urls`；没有时从平台当前首页的可见导航进入。
   - 不凭记忆拼接子域名或路径；保存重定向后的最终 URL。
   - 先确认浏览器标签页对用户可见；后续验证与人工接管必须继续使用该标签页。
2. 先执行不带偏好区域词的全市/全边界基线。平台支持时优先组合面积与总价/总成本筛选，再应用用户明确的价格下限和排除规则；软偏好区域、线路或商圈留到后续通道，不用来替代基线。
3. 每个通道持续翻页或滚动，逐页记录到 `collection_log.json`。翻页后先核对面积、价格、交易类型等已选条件和结果范围仍然生效；条件丢失的页面不计入已检查页，恢复失败则以 `blocked` 终止并记录截图和原因。20–50 条只是候选池参考，不能作为停止理由；停止条件见 `discovery-coverage-rules.md`。
4. 打开高潜广告详情页，记录具体字段，不只抄搜索结果卡片。
5. 保存页面 URL、抓取时间、可见更新时间、原始报价口径。
6. 保存 1 张页面证据截图；Top 候选再保存 2–6 张决策图片。
7. 浏览器支持且合法时，把高潜详情页 HTML 保存到 `evidence/pages/`，后续由 `extract_saved_html.py` 解析；解析器本身不联网。
8. 完成后记录 `completed_with_results` 或 `completed_zero_results` 和数量；受限时记录明确的 blocked/access 状态并进入人工接管等待，不记录替代来源。来源状态只能在该来源所有计划搜索通道已终止后标记完成。

高优先级来源先执行。搜索引擎无该站结果不算完成平台尝试；应直接访问平台公开入口，或记录真实的访问限制。

## 结构化输入优先

搜索结果或用户提供的数据已经是 CSV/XLSX/JSONL/HTML table 时，优先 `bulk_import.py`，不要逐条复制。字段映射复用 `field-aliases.json`。页面详情仍应保留 URL/截图用于证据核验。

## 保存 HTML

建议：`evidence/pages/<platform>/<source_id>_<YYYYMMDD-HHMM>.html`。页面解析输出放 `evidence/page_extracts/`。自动提取存在冲突时回到浏览器页面人工确认，禁止按“最低数值”自动消歧。

## 截图命名

建议：

```text
evidence/screenshots/<platform>/<source_id>_<YYYYMMDD-HHMM>_<page|price|unit>.png
assets/images/<source_id>_<interior|exterior|street|public_area>_<nn>.jpg
```

截图用于证据；HTML 展示图用于快速初筛。两者可以相同，也可以分开。

## 页面内容优先级

优先读取：具体项目、地址、面积、楼层/房号、报价、物业费/税费、更新时间、经纪/业主身份、房源状态、经营限制、图片。

广告标题中的“特价、最后一套、业主急租”仅作为营销文本记录，不自动转化为事实。

## 验证码

只有用户可见、当前受控的浏览器标签页明确出现 CAPTCHA、滑块、短信、二维码登录或二次验证时才进入人工接管；404、空白页、超时、连接失败，以及后台抓取工具返回的验证码文本都不算已确认验证码。

出现验证后立即停止自动操作，保存当前 URL、页面截图和状态，确认当前浏览器页面保持可见，并请用户在该页手动完成。若发生在必查主源，同时停止所有其他房源平台工作。用户确认完成后继续使用同一标签页；第一次成功恢复操作时把来源状态改回 `in_progress` 并清除等待标记，再从中断的通道继续。禁止刷新、重开或用另一个浏览器会话替代，除非用户明确同意。

后台抓取工具若返回验证码页，不得暂停任务或请用户处理该后台响应。先在用户可见浏览器中打开来源注册表入口并复现；未复现时只记录“辅助访问异常”，继续以可见浏览器的实际页面为准。

## 限流与反爬

遇到持续限流、封禁、明确禁止自动访问：不要模拟绕过、改造指纹或规避访问控制。若发生在必查主源，保持页面并等待用户决定；不得自行切换来源继续交付。

## 多 worker 并行

按来源拆 worker，而不是按“搜房/筛房/总结”随机拆。每个 worker 只写自己的 `raw_listings_<worker>.json`，结束后用 `merge_raw_listings.py` 合并，避免并发写同一 JSON 文件。
